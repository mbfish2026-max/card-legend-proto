# 药水扩展方案：强效/超级药水、太阳水、强效太阳水、药水捆

> feat/potion-doc 出方案；**feat/potion-expand 已实现 P1 数据 / P2 解包 / P3 药店 / P5 UI**，P4 用药与 P6 掉落平衡留给战斗开发（见 §8）。§1.1 的数值和 §2 的捆规格已拍板，按表实现。

标记说明：**[官方]** 指资料站上的 1.76 版数据，附链接；**[适配]** 指本作为了玩法做的改动；**[未查到]** 指没找到可靠出处，没有编数。

## 0. 现状（main 2ec2065）
- `src/data/skills.ts` POTIONS 共 4 种：hp_small（HP120，count5，20 金）、hp_mid（HP320，count2，60 金）、mp_small（MP90，count5，20 金）、mp_mid（MP240，count2，60 金）。数值已经按本作血量放大过 [适配]。
- 用药：`World.usePotion`，HP 和 MP 冷却各自独立，`WORLD.potCd=1.0s`；回复走 HoT，`potHotSec=0.5`，分 `potHotTicks=2` 跳。
- 持有量：`World.pots:number[]`，按 POTIONS 下标计数，存在 `save.pots` 里。药水不进背包格。背包 `bagSize=200`，堆叠上限 `BAG_STACK_MAX=999`（bagSort.ts）。
- 药水栏：桌面 1–4 热键；手机 `#mh-pots` 有 4 格，`POT_CSS=56`，`POT_FRAME=[7,8,7,8]`，`POT_ICON=56-8-8-4=36px`（src/ui/potFrame.ts）。
- 以前的处理（docs/drops-official.md）：太阳水、强效太阳水标「本作无此物品，未接入」，强效药并进中量药 [适配]。

## 2. 捆（药水包）规格
- 每捆 6 瓶 [官方旁证]。捆名沿用官方：金创药(小)包、魔法药(小)包、金创药(中)包、魔法药(中)包、超级金创药、超级魔法药、强效太阳水包；太阳水包 [适配，官方没有]。
- 价格：官方捆比 6 瓶单买略贵（680 对 480，3400 对 3300），本作建议**捆 = 单价×6，不打折也不加价**[适配]。避免出现「买捆再拆」的套利，也不惩罚批量买。
- 捆是背包物品（ITEMS 新增 `bundle:{pot:key,n:6}`），占 1 格，可堆叠到 `BAG_STACK_MAX=999`。
- 双击解包：从背包里扣 1 捆，`pots[idx]+=6`。散装药水还是 `pots` 计数，**不占背包格**（这样不用改药水栏）。拆成功写日志「解开 金创药(小)包，获得 6 瓶」。
- 散装单种上限：建议 `POT_MAX=999`。超过上限就拒绝拆，提示「药水已满」，不吞药 [适配]。
- 战斗中能不能拆：建议可以（官方允许），手机端双击/长按菜单「解开」。
- 药店：散装和捆同时卖，捆放在列表下方；数量按钮 ×1/×5/×10 捆 [适配]。卖回给商店按买价的 1/2（沿用现有回收规则；没有就标待定）。

## 3. 掉落 / 商店范围
- 商店：小/中散装与捆从 Lv1 开始卖；强效散装与超级捆 Lv22 起卖；太阳水 Lv22 起；强效太阳水只卖捆，Lv35 起 [适配]。
- 掉落：按 docs/drops-official.md 已整理的官方太阳水/强效太阳水爆率，接到对应怪身上（本作有这只怪才接，没有就不接）。强效金创/魔法药也接官方掉落名单（尸王、祖玛卫士、沃玛卫士、牛魔法师等）。捆不掉落（资料站写「暂无掉落数据」）。
- 掉落的药直接 `pots[i]++`，和现有 def.potion 路径一样。

## 4. 平衡影响与评估方案（给战斗开发，本分支不改战斗逻辑）
- 风险：太阳水是立刻回复，会绕过 0.5s HoT，战士高压段死亡数可能明显下降；强效药提高单次回复量，sim 买药策略也要跟着改。
- 方案：用 9 seed `[3,7,11,19,23,42,57,88,101]` 跑 `tests/sim-band.ts warrior|mage|taoist` 到 50 级。对照组是 main（中位数：战 死亡20/t14005，法 6/7471，道 14/15338，b044c21），实验组 A 只加强效药，实验组 B 再加太阳水。指标：死亡中位数、有损失死亡（PASS_MAX_DEATHS=14）、到 50 级用时、金币曲线、药水消耗量。1–39 指纹变化要单独列出来。
- 给战斗开发的问题：
  1. 太阳水的立刻回复走 `addHot` 改 0 跳，还是新开 `instantHeal`？要不要单独开一个冷却位（hero.sunReady）？
  2. sim 自动买药和英雄自动用药（hejiban 阈值 HP<50% MP<30%）选药优先级怎么定？建议普通药优先，太阳水留到 HP<30% 时用。
  3. 血石 `tickStone`（灵符商城血石，charge{hp,mp}）和太阳水同时触发时，是否叠加？建议血石先结算。
  4. 如果实验组 B 让战士死亡数降到基线以下太多，是靠调价格/等级门槛压，还是调回复量？
  5. sim-lib 是否需要模拟「拆捆」（建议不需要，直接把买捆当成 +6 瓶）。

## 5. 与其它系统的关系
- **药水栏 UI（已拍板，feat/potion-expand 实现）**：桌面和手机都只有 **3 格：红 / 蓝 / 太阳水**，不扩到 1–6。每格显示当前选中药的图标和数量；**长按（≥450ms，桌面也可右键）弹层换本类的药**（红：小/中/强效；蓝：小/中/强效；太阳水：太阳水/强效太阳水），点弹层外关闭。手机格仍 `POT_CSS=56`、图标 36px 居中、数量在右下角 span（沿用 potFrame.ts），弹层选项 52×52。选择存档 `save.potSel`（3 个 key），默认选每类有货的最低级。代码：src/ui/potBar.ts（PotBarDesk / PotBarDom），Hud.ts / MobileHud.ts 只各换了一处调用。
- **key 合并（已实现）**：旧物品 `hp_strong / mp_strong / sun_water`（items-town 时期的背包消耗品）并入 `hp_big / mp_big / sun`，全游戏只有一种强效金创药。读档 `migratePots`（src/data/potions.ts）：主角背包/仓库里的旧 key 物品和散装药物品折进 `pots`（单种上限 999，溢出部分保留为新 key 物品），英雄包裹里的旧 key 改名；数量不丢。单测 tests/potion-expand.test.ts。
- **灵符商城**：不卖药（已拍板）。
- **血石 tickStone**：血石是持续自动回复，和药水冷却互不占用。两者叠加的上限需要战斗开发确认（见 §4 Q3）。
- **存档兼容**：`save.pots` 是按下标的数组，**新药只能追加到 POTIONS 末尾**（下标 4、5、6、7），旧档长度短，读档时补 0（`pots[i] ??= 0`）。捆进 `save.bag`（物品 id），旧档没有就不用迁移。不要改现有 4 种的下标和 key。加 `saveVersion` 校验单测：旧档读入 → pots 长度为 8 → 原 4 项数值不变。

## 8. 实现状态与战斗接入点（feat/potion-expand）
已实现：
- P1：POTIONS 下标 4–7 = hp_big / mp_big / sun / sun_big（key `P4`–`P7`，`lv`、`instant`、`bundleOnly` 字段）；ITEMS 加 4 种药和 8 种捆（`bundle:{pot,n:6}`）；旧 key 迁移。
- P2：背包里捆显示数量；桌面 450ms 内双击、手机「点一下选中，再点一下」解开 1 捆，散装 +6；超过 999 拒绝且不扣捆。`World.unbundle(bagIdx)`。
- P3：药店散装和捆同列（捆在下方），等级不够灰显「需LvX」；强效太阳水只卖捆（Lv35）。`World.buyPotion / buyBundle`。旧「商店」面板只列原 4 种。
- P5：3 格药水栏 + 长按换药（见 §5）。
- API：`World.getSelectedPotion(slot)` → key；`selectedPotionIndex(slot)` → POTIONS 下标；`setSelectedPotion(slot, key)` 只接受本类的药。

**当前行为（未改战斗代码）**：点药水格 = `BattleScene.onKey(POTIONS[选中].key)` → `World.usePotion(i)`。所以新药现在走的是**旧规则**：强效药按 HoT 0.5s；**太阳水也是 HoT，不是立刻**，而且同时占用 HP 和 MP 两个冷却位。键盘 1–4 仍对应原 4 种药，**没有改成 1–3 = 三格**。

留给战斗开发（P4 / P6）：
1. 热键 1–3 → `usePotion(world.selectedPotionIndex(slot))`（BattleScene.onKey），并决定原 4 键是否保留。
2. `instant` 药（sun / sun_big）立刻回复 + 单独冷却位（建议 `hero.sunReady`），不占红蓝冷却。
3. 自动用药 / 英雄 AI / sim-lib 的选药优先级（英雄的 POT_TABLE 已含强效药与太阳水，数值随 §1.1 改了：强效 600→560，太阳水 300/200→180/240）。
4. 拾取掉落药不检查 999 上限（掉落逻辑未改）。
5. P6：接官方掉落表，并在接入用药后重跑 9 seed 平衡对比。本分支的 sim 输入（World.ts、drops-s9、items、skills、potions）有改动，但 sim-band 战/法/道 9 种子的输出和 main 2ec2065 逐行一致。drops-s9 的强效药/太阳水掉落现在进 `pots`（原来进背包）。

### 8.x 手机点按时序修复
手机双击解包不稳的根因与修法见 CHANGELOG（flushInput / 选中时不自动重绘 / 长按按事件时间戳）。验证：potion-expand-verify 在 844×390、874×402、932×430 各连跑 10 次（第二下间隔随机 200–1100ms，`GAP=1`）全过，1280×720 连跑 5 次全过。
