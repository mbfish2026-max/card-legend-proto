# 层长 + 怪量 + 层结构（feat/balance-sys 任务 A/B/C）

## 任务 A：层宽与怪量 [适配]
- 官方传奇地图是 2D 格子地图（如比奇 ~800×600 格），和本作的横版卷轴没法直接换算，**官方对应宽度未查到**，屏数按需求规则取：
  - 第一张图（幽暗森林）5 屏；
  - 普通层 6–8 屏（多层图第 2 层 +1，BOSS 层 +1）；
  - 洞穴/殿/墓/矿/寺庙等，或深度 ≥3 的层，8–10 屏。
  - 规则在 `widthRule`（src/data/world.ts）。1 屏 = 1280px，旧版统一是 3 屏（`OLD_MAP_W` = 3840）。
- 普通怪倍率 `monsterMult`：5 屏 ×1.8，线性涨到 10 屏 ×2.5，按 ×1.8–2.5 夹取（官方刷怪量未查到）。
  - 旧布局按「包」（间距 ≤300px）循环复制，包中心沿 [800, 第一只 BOSS−700] 均匀铺开。
  - 入口 800px 内不放怪。
  - 任意 1280px 窗口内最多 6 只（PER_SCREEN_CAP），由测试保证。
- BOSS 数量不变，离右端的距离和旧版相同，所以 BOSS 房仍在最右端。
- 出口 `exitX = mapW − 160`。heroStartX 仍为 220。相机、小地图、背景平铺（镜像拼接，不拉伸）都用 `World.mapW`。
- 沃玛寺庙的分段和教主之家门（WOMA_DOOR_X）按层宽等比缩放。保底号角改为「门前的怪清完」就给，修掉层加长后门后有怪导致的死锁。
- 性能：离主角超过「半屏 + 2 屏」的待机怪进入休眠。压力测试是单层 120 只怪，单帧 step 远低于 4ms 预算（见 tests/balance-sys.test.ts）。
- 旧存档：存档里不保存主角坐标（只有 floorIndex），读档时按新层宽从 heroStartX 开始，不存在越界坐标；地面掉落/区域按当前 mapW 夹取。
- 模拟器（tests/sim-lib.ts）：
  - `SIM_MAX_T` 从 7200×4 放宽到 7200×6。这只是防死循环的上限，不是验收指标；层长约 ×2.3，按比例放宽。
  - 新增 `SIM_STUCK` = 5：同层连死 5 次，就回上一层虚拟刷 1 级，模拟玩家卡关后练级。死亡照常计数，没有放宽任何测试目标。
